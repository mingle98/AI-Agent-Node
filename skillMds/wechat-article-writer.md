# WeChat Article Writer

帮助用户生成适合微信公众号发布的文章，重点不是“普通长文”，而是更符合公众号阅读习惯的内容形态：

- 标题抓人但不过度标题党
- 开头要快，前 3 段建立阅读动力
- 正文结构清晰，适合手机端滑读
- 有观点、有信息、有节奏
- 结尾自然引导关注、评论、转发或行动

## 适用场景

- 品牌内容运营
- 产品更新 / 新功能发布
- 创始人观点表达
- 行业观察与趋势解读
- 活动预热 / 复盘总结
- 个人 IP 内容输出
- 知识科普 / 方法论文章

## 输出目标

写出来的文章应该满足：

1. **用户愿意点开**：标题有明确利益点、冲突点或新鲜感
2. **用户愿意读下去**：开头迅速进入主题，不过度铺垫
3. **用户容易读完**：段落短、节奏清晰、重点突出
4. **用户读完有感受**：有观点、有案例、有一句能记住的话
5. **用户愿意互动**：结尾有自然行动引导

## 默认工作流

### Step 1：先判断文章任务类型

优先识别用户要的是哪一类公众号文章：

- **观点型**：表达立场、观察、判断
- **干货型**：总结方法、经验、框架
- **故事型**：人物、经历、案例、幕后过程
- **发布型**：产品、活动、功能、公告
- **复盘型**：项目总结、数据复盘、经验沉淀
- **热点借势型**：结合新闻、行业动态输出观点

如果用户信息不足，先用一句话补齐以下关键缺口：

- 面向谁写
- 想达到什么传播目标
- 文章基调（专业 / 真诚 / 犀利 / 克制 / 温暖）
- 是否有必须保留的信息点

## Step 2：先给结构，再展开正文

如果用户只给主题，不要一上来直接写满篇正文。优先先给：

1. 选题角度
2. 标题候选 3-5 个
3. 文章结构大纲
4. 开头切入方式

确认方向后再写正文。

## Step 3：公众号文章推荐结构

### 结构 1：问题 → 分析 → 观点 → 建议

适合：行业观察、趋势评论、方法总结

```markdown
标题
开头：抛出现象 / 冲突 / 常见误区
一、问题到底是什么
二、为什么会这样
三、真正重要的判断
四、普通人/企业应该怎么做
结尾：一句总结 + 引导互动
```

### 结构 2：故事 → 转折 → 方法 → 总结

适合：个人经历、案例拆解、幕后复盘

```markdown
标题
开头：一个具体场景或故事片段
一、事情是怎么发生的
二、真正的转折点是什么
三、我学到了什么 / 提炼出什么方法
四、给读者的启发
结尾：金句收束 + 提问
```

### 结构 3：结论前置 → 证据展开 → 行动建议

适合：品牌发声、创始人观点、产品洞察

```markdown
标题
开头：先说结论
一、为什么我这么判断
二、有哪些信号支持这个判断
三、这意味着什么
四、接下来应该怎么做
结尾：简短有力地收住
```

## 标题写法

标题优先满足“明确 + 有信息量 + 有传播性”，避免空泛。

### 常见标题方向

- **结果型**：我们用 30 天，把公众号打开率从 6% 做到 18%
- **观点型**：大多数公众号难做，不是因为不会写，而是没想清楚写给谁
- **反常识型**：比起拼命追热点，公众号更该先解决“可持续表达”
- **清单型**：写公众号最常见的 7 个问题，我踩过 5 个
- **提问型**：为什么你的公众号文章总是“写得认真，但没人看”？

### 标题规则

- 尽量具体，不要太空
- 有对象、有问题、有结果更好
- 不要为了点击率堆砌夸张词
- 同一主题至少给 3 个备选标题

## 开头写法

公众号文章的前 3 段决定大部分读者会不会继续看。

推荐开头方式：

### 1. 直接抛问题

```markdown
很多人写公众号时最痛苦的一件事，不是不会写，而是不知道到底该写给谁看。
```

### 2. 从真实场景切入

```markdown
前几天一个朋友问我：为什么他每周都认真更新，但公众号阅读量还是起不来？
```

### 3. 先给结论

```markdown
如果公众号只能优化一件事，我建议先改开头，而不是改排版。
```

## 正文写法要求

### 段落节奏

- 手机端优先，段落短一点
- 一段尽量只讲一个重点
- 关键句单独成段
- 长段落中间要有小标题或过渡句

### 语言风格

- 说人话，不堆术语
- 可以专业，但不要僵硬
- 尽量让句子有节奏感
- 不要整篇都像 PPT 汇报

### 增强可读性的方式

- 小标题分段
- 列表归纳
- 黑体强调关键词
- 加案例、类比、对比
- 适度加入一句“点醒式”表达

## 结尾写法

结尾不要泄气，也不要机械喊关注。

推荐方式：

- **总结式**：再收一次核心观点
- **提问式**：引导评论区交流
- **行动式**：引导转发、收藏、试用、报名
- **余味式**：留下一句值得记住的话

示例：

```markdown
说到底，公众号不是“写得越多越好”，而是“越知道写给谁越好”。

如果你也在做内容，不妨先想清楚：你最想影响的那群人，到底是谁？
```

## 推荐输出格式

根据用户需求，优先输出以下其中一种：

### 模式 A：策划优先

```markdown
1. 文章定位
2. 目标读者
3. 标题备选
4. 大纲结构
5. 开头示例
6. 配图建议
```

### 模式 B：直接成稿

```markdown
# 标题
## 摘要 / 导语（可选）
正文
结尾
```

### 模式 C：优化改写

用于用户已经有初稿时：

```markdown
1. 原稿问题诊断
2. 结构优化建议
3. 标题优化
4. 改写后的版本
```

## 配图建议

如果用户需要公众号配图建议，优先给：

- 封面图方向
- 文中分隔图建议
- 数据图 / 截图 / 插画建议
- 每张图放在哪一部分最合适

配图建议应服务文章内容，不要为了“好看”而加无意义插图。

## 公众号排版输出约定

默认按“适合直接复制到公众号编辑器”的形式输出：

- 段落尽量短，一般 1-3 句一段
- 小标题明确，避免整篇没有呼吸点
- 关键句可以单独成段
- 列表优先用短 bullet，不写过长并列句
- 避免大段学术化表达和过密长句
- 如无特别要求，不输出复杂 markdown 表格

如果用户明确说“直接给我可发版”，优先输出：

```markdown
标题

导语

小标题一
正文

小标题二
正文

小标题三
正文

结尾
```

如果用户明确说“只要内容，不要解释”，就直接给最终成稿，不附加分析过程。

## 风格原则

- **真诚比华丽重要**
- **清晰比辞藻重要**
- **观点比堆信息重要**
- **传播性重要，但不要廉价标题党**
- **优先帮助用户完成表达，而不是炫技巧**

## 使用提示

当用户请求涉及以下内容时，优先使用本 skill：

- “帮我写一篇公众号文章”
- “给我起几个公众号标题”
- “这段内容改成公众号风格”
- “帮我做一篇适合微信公众平台发布的文章”
- “把这篇内容改得更适合传播”
- “帮我润色成微信公众号推文”
