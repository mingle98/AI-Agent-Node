# Python 数据分析与执行防呆指南（当前实现适配版）

本文聚焦一个现实问题：

**当前项目虽然支持 Python 脚本生成与执行，但如果不给 Agent 明确约束，它很容易生成“看起来对、实际跑不起来”的脚本。**

本文目标是：
- 降低 Python 脚本生成失败率
- 降低第三方依赖导致的执行失败
- 降低因输入不完整而生成无效脚本的概率
- 提升数据分析/计算类任务的稳定体验

---

## 1. 当前 Python 执行能力的真实边界

当前项目支持：
- 生成 Python 脚本
- 执行 Python 3 脚本
- 捕获 stdout / stderr
- 超时控制（30 秒）
- 简单安全检查
- 对执行结果做二次分析

当前项目不应被描述为：
- 带完整 Python 环境的 notebook
- 可稳定安装任意第三方依赖的分析环境
- 可访问项目 JS 工具模块的 Python 运行时
- 可联网拉包、拉数据、调用外部 API 的 Python 沙箱

---

## 2. 最重要的执行约束

### 2.1 只用 Python 标准库
这是最重要的一条。

当前脚本生成提示词已经明确要求：
- 只使用 Python 标准库
- 禁止使用：
  - `numpy`
  - `pandas`
  - `matplotlib`
  - 以及其他第三方库

因此知识库必须强化：

**凡是能用标准库完成的任务，绝不生成第三方依赖脚本。**

### 2.2 不要依赖外部文件，除非任务明确要求
默认情况下，生成的 Python 脚本应：
- 自包含
- 直接处理用户给出的输入数据
- 不假设本地一定存在某个文件

### 2.3 不要默认联网
不应生成：
- 下载数据
- 调用 HTTP API
- 在线安装依赖
- 请求外部服务

### 2.4 必须可独立运行
脚本应满足：
- 复制出来即可执行
- 有 `try/except`
- 所有结果通过 `print()` 输出
- 不依赖交互输入

---

## 3. Agent 何时该使用 Python

适合使用 Python 的场景：

1. 需要做明确的数值计算
2. 需要做分步统计
3. 需要做简单文本提取/转换
4. 需要做结构化结果输出
5. 单靠自然语言总结不够稳时

例如：
- 漏斗转化率计算
- 加权评分
- 简单均值/中位数/标准差
- JSON/CSV 文本转换
- 文本中的数字提取
- 简单规则判断

---

## 4. Agent 何时不要优先使用 Python

以下情况不要默认走 Python：

### 4.1 纯概念问答
例如：
- 什么是转化率
- Python 和 JavaScript 有什么区别

### 4.2 需要复杂第三方科学计算库
例如：
- 用 pandas 清洗大型表格
- 用 matplotlib/seaborn 画图
- 用 sklearn 建模

因为当前环境不应承诺这些依赖可用。

### 4.3 需要读外部未知文件，但用户没给路径
这种情况应先澄清数据来源。

### 4.4 用户数据不完整
例如：
- “帮我算转化率”但没给任何数据
- “帮我做预测”但没有历史样本

应先补齐输入，而不是硬生成脚本。

---

## 5. Python 任务分流 SOP

收到 Python / 数据分析类请求时，优先判断成以下几类：

1. **直接计算型**
2. **统计分析型**
3. **漏斗/转化型**
4. **文本处理型**
5. **格式转换型**
6. **复杂建模型**

其中：
- 前 5 类通常适合当前项目
- 第 6 类要谨慎，不能默认承诺

---

## 6. 各类 Python 任务的稳定做法

## 6.1 直接计算型
适用：
- 求和
- 平均值
- 最大最小值
- 加权评分
- 简单公式计算

推荐做法：
- 直接用标准库或原生运算
- 输入数据尽量明确成数组、键值对或简单字段

推荐输入形式：
- `10, 20, 30, 40`
- `A=80, B=92, C=75`
- `成本=80, 质量=90, 交付=75`

---

## 6.2 统计分析型
适用：
- 平均数
- 中位数
- 标准差
- 计数
- 分布摘要

推荐做法：
- 使用 `statistics` 标准库
- 对样本数量不足的情况加保护

注意：
- 样本少于 2 个时，标准差可能不适用
- 不要生成依赖 `numpy` 的脚本

---

## 6.3 漏斗 / 转化型
适用：
- exposure -> click -> signup -> pay
- 多步骤业务转化率计算

推荐做法：
- 明确各阶段名称和数量
- 输出：
  - 各阶段转化率
  - 整体转化率
  - 最大流失环节

推荐输入形式：
- `exposure=120000, click=8400, signup=2100, pay=315`

如果数据字段不明确：
- 先追问阶段定义，不要猜业务口径

---

## 6.4 文本处理型
适用：
- 正则提取
- 字符串清洗
- 关键词统计
- 文本格式转换

推荐做法：
- 使用标准库：`re`, `json`, `csv`, `collections`
- 不依赖 NLP 第三方库

---

## 6.5 格式转换型
适用：
- JSON 转 CSV
- CSV 文本重排
- 简单结构化文本转换

推荐做法：
- 使用标准库 `json`, `csv`, `io`
- 输入内容尽量由用户直接提供
- 不要假设一定要读本地文件

---

## 6.6 复杂建模型
例如：
- 回归模型
- 聚类
- 机器学习训练
- 图像处理

当前建议：
- 不要轻易承诺可直接执行
- 先说明当前 Python 执行环境更适合标准库级轻量分析
- 若要继续，应降级成：
  - 思路说明
  - 伪代码
  - 结构化方案
  - 非执行型脚本草稿

---

## 7. 生成脚本时的硬性要求

每次生成 Python 脚本，都应尽量满足：

1. 只使用标准库
2. 包含 `try/except`
3. 不依赖交互输入 `input()`
4. 不依赖网络
5. 不依赖外部安装包
6. 不依赖未知文件路径
7. 通过 `print()` 输出结果
8. 输出结构尽量清晰，可读或可解析

推荐输出形式：
- 文本摘要
- JSON
- CSV 文本

---

## 8. 最常见失败原因与规避方式

## 8.1 使用了第三方库
高风险示例：
- `import pandas as pd`
- `import numpy as np`
- `import matplotlib.pyplot as plt`

规避规则：
- 一律改成标准库实现
- 如果任务本质上依赖这些库，就不要假装可执行

---

## 8.2 假设有本地文件
高风险示例：
- 默认读 `data.csv`
- 默认读 `/tmp/input.json`

规避规则：
- 除非用户明确给文件路径，否则直接处理文本输入

---

## 8.3 输入数据不完整
高风险示例：
- 没有数字却要统计
- 没有阶段数量却要算转化
- 没有格式示例却要做转换

规避规则：
- 先问清输入
- 不要靠臆测补数据

---

## 8.4 输出不可消费
高风险示例：
- 只输出一堆零散 print
- 没有结论、没有结构

规避规则：
- 要么输出清晰文本报告
- 要么输出 JSON / CSV
- 最好给关键结论字段

---

## 8.5 执行时间过长
当前超时限制：**30 秒**

规避规则：
- 不生成大循环、死循环
- 不生成重型计算
- 不生成大规模暴力枚举

---

## 9. 推荐追问模板

### 计算类
- 你可以把要计算的数据直接发给我吗？最好是逗号分隔数字，或者 `字段=数值` 的形式，这样我能生成更稳的可执行脚本。

### 漏斗类
- 请把每个阶段和对应数量发给我，比如 `exposure=120000, click=8400, signup=2100, pay=315`，这样我能准确计算各阶段转化率。

### 转换类
- 你希望转换的原始内容是什么格式？最好直接贴一小段样例，我会按这个样例生成更稳的脚本。

### 复杂分析类
- 如果你这个任务依赖 pandas / numpy / sklearn 这类库，当前运行环境不适合直接承诺执行。我可以先给你一版标准库可执行方案，或者给你非执行型脚本草稿。

---

## 10. 不应误导的表述

以下说法不要出现：

- “我可以直接用 pandas 帮你跑”
- “我可以联网安装依赖后执行”
- “我会直接读取你本地某个文件”
- “我可以稳定运行任意 Python 数据科学脚本”
- “复杂建模任务都可以直接在这里跑起来”

---

## 11. 推荐降级路径

当任务超出当前 Python 执行边界时，按下面顺序降级：

### 降级 1：从执行脚本改为给结构化思路
适合：
- 数据不足
- 任务目标太模糊

### 降级 2：从第三方库方案改为标准库方案
适合：
- 原本想用 pandas/numpy

### 降级 3：从可执行方案改为伪代码/草稿
适合：
- 任务必须依赖复杂库

### 降级 4：从脚本执行改为结果公式或手工计算说明
适合：
- 其实只是简单计算

---

## 12. 一句话结论

当前项目里，Python 最稳的使用方式是：

**只做标准库可完成的轻量计算、统计、文本处理和格式转换；输入先补齐，脚本要自包含、可直接运行、无第三方依赖。**
