# 数据分析任务模式库（当前实现适配版）

本文不是泛泛讲“数据分析怎么做”，而是帮助 Agent 判断：

- 什么分析任务适合当前项目直接执行
- 什么输入格式最稳
- 什么输出格式最合适
- 什么任务该先追问，什么任务不该硬跑 Python

---

## 1. 当前项目最适合的分析任务类型

当前项目最适合承接的，是这几类**轻量、规则明确、可用标准库完成**的任务：

1. 基础统计
2. 漏斗/转化率计算
3. 加权评分
4. 简单文本数据提取
5. JSON / CSV 结构转换
6. 小规模结果整理

不应默认承接为“可稳定执行”的任务：
- 大规模数据分析
- 依赖 pandas / numpy / matplotlib
- 机器学习训练
- 高级回归建模
- 复杂时间序列预测

---

## 2. 输入格式优先级

为了提高执行成功率，Agent 应引导用户尽量使用以下输入形式：

### 优先级 1：键值对输入
例如：
- `exposure=120000, click=8400, signup=2100, pay=315`
- `成本=80, 质量=90, 交付=75`

适合：
- 漏斗
- 加权评分
- KPI 对比

### 优先级 2：逗号分隔数字
例如：
- `10, 20, 30, 40, 50`

适合：
- 平均值
- 中位数
- 最大最小值
- 波动分析

### 优先级 3：小段 JSON
例如：
- `[{"name":"A","score":80},{"name":"B","score":92}]`

适合：
- 简单结构化转换
- 小规模字段提取

### 优先级 4：小段原始文本样例
例如：
- 一小段日志
- 一小段半结构化文本

适合：
- 文本提取
- 规则匹配

## 3. 任务模式与推荐输出

## 3.1 基础统计任务
常见表达：
- 算平均值
- 算最大值和最小值
- 做个简单统计
- 看一下这组数的波动

推荐输入：
- 逗号分隔数字

推荐输出：
- `summary`
- 如需结构化可输出 `json`

适合直接执行：是

---

## 3.2 漏斗 / 转化率任务
常见表达：
- 计算漏斗转化率
- 找出流失最大的环节
- 看看整体转化情况

推荐输入：
- `exposure=120000, click=8400, signup=2100, pay=315`

推荐输出：
- `summary`
- 若后续还要继续处理，可输出 `json`

适合直接执行：是

必须先确认：
- 各阶段名称
- 阶段顺序
- 分母口径

---

## 3.3 加权评分任务
常见表达：
- 帮我做个加权评分
- 比较几个方案谁更合适
- 按权重打分

推荐输入：
- `产品A(成本80,质量90,交付75)，产品B(成本70,质量85,交付90)，权重成本0.4,质量0.3,交付0.3`
- 或显式键值结构

推荐输出：
- `summary`
- `json`

适合直接执行：是

注意：
- 如果权重总和不为 1，要提醒或自动标准化并说明

---

## 3.4 文本提取任务
常见表达：
- 从这段文本里提取邮箱
- 统计关键词出现次数
- 把日志中的错误码提取出来

推荐输入：
- 小段原始文本

推荐输出：
- `summary`
- `json`
- 如是清单型结果，也可输出 `csv` 文本

适合直接执行：是

注意：
- 最好让用户给样例文本
- 规则越明确，脚本越稳

---

## 3.5 格式转换任务
常见表达：
- 把 JSON 转成 CSV
- 把这段结构化文本整理一下
- 输出成图表可用的数据

推荐输入：
- JSON 样例
- 小段 CSV / 文本样例

推荐输出：
- `json`
- `csv`
- `chart_data`

适合直接执行：是

---

## 3.6 图表数据准备任务
常见表达：
- 给我一个能画图的数据结构
- 帮我整理成 ECharts 能用的格式

推荐输入：
- 时间序列数据
- 类目 + 数值数据

推荐输出：
- `chart_data`
- `json`

适合直接执行：是，但不要默认画图

当前更适合：
- 先生成图表数据结构
- 再交给图表能力渲染

## 4. 什么时候必须先追问

以下情况不要直接执行：

### 4.1 用户没给数据
例如：
- 帮我算转化率
- 帮我做统计

推荐追问：
- 请把原始数据直接发给我，最好是数字列表、键值对，或者一小段 JSON 样例。

### 4.2 业务口径不清
例如：
- 帮我算增长率
- 帮我看 ROI

推荐追问：
- 请确认下口径：分子和分母分别是什么、时间范围是什么、是否有对比基期？

### 4.3 数据规模可能很大
例如：
- 几十万行数据
- 大体量 CSV

推荐追问：
- 当前更适合轻量分析。你可以先提供一小段样例或明确目标，我先帮你验证分析逻辑，再决定是否输出更完整方案。

### 4.4 任务本质依赖第三方库
例如：
- 用 pandas 清洗复杂表格
- 用 sklearn 做预测

推荐回应：
- 当前执行环境更适合标准库级轻量分析。我可以先给你一版可执行的简化方案，或者给你完整思路与脚本草稿。

---

## 5. 推荐输出格式选择

### 用 `summary`
适合：
- 用户只想看结果结论
- 任务偏解释性

### 用 `json`
适合：
- 后续还要继续加工
- 用户要结构化数据
- 结果需要给其他工具消费

### 用 `csv`
适合：
- 结果天然是表格
- 用户想导入表格工具

### 用 `chart_data`
适合：
- 用户下一步想做图
- 结果需要对接可视化能力

---

## 6. 推荐工作方式

### 模式 A：先算再解释
适合：
- 明确计算任务
- 数据较完整

流程：
1. 生成自包含脚本
2. 执行
3. 输出结果
4. 给简要解释

### 模式 B：先确认输入再执行
适合：
- 用户描述模糊
- 缺数据
- 口径不清

流程：
1. 追问最少必要信息
2. 收到样例后再生成脚本

### 模式 C：先给结构草稿
适合：
- 复杂分析
- 可能超出执行边界

流程：
1. 给思路 / 结果结构
2. 再决定是否执行

---

## 7. 常见高风险请求与建议处理

### “帮我用 pandas 清洗一下”
建议处理：
- 不直接承诺执行
- 改为标准库方案，或说明环境边界

### “帮我预测明年趋势”
建议处理：
- 先问历史数据和预测方法
- 不要假装可以直接做可靠预测

### “帮我跑个机器学习模型”
建议处理：
- 不直接执行
- 先给方法框架、伪代码或脚本草稿

### “帮我把这堆文件都分析一下”
建议处理：
- 不直接塞给 Python
- 先明确数据来源和格式

---

## 8. 不应误导的说法

不要说：
- “任何数据分析我都能直接跑”
- “我可以直接用 pandas/numpy/sklearn”
- “我会自动理解你的业务指标口径”
- “没有数据我也能直接给出可靠计算结果”

---

## 9. 一句话结论

当前项目最适合的数据分析方式是：

**围绕标准库可完成的轻量计算、统计、转化率、加权评分、文本提取和格式转换展开，先把输入格式收敛，再执行可自包含脚本。**
