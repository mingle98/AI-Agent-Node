# Office 与文件处理能力支持矩阵（当前实现对齐版）

本文只描述**当前项目代码里已经实现或可以明确推断出的能力**，避免把通用 Office 常识误写成项目能力。

适用范围：
- 项目：`AI-Agent-Node`
- 当前代码实现：仓库当前版本
- 目的：给 Agent 提供**可落地、少误导**的文件处理判断依据

---

## 1. 总体原则

### 1.1 先区分“允许上传”和“可被结构化处理”
项目里文件上传接口允许多种扩展名进入 workspace，但这**不等于**系统对这些格式都具备深度解析/编辑能力。

应遵循下面的判断：

- **允许上传**：表示文件可以进入用户 workspace。
- **支持读取文本/结构**：表示工具可以可靠提取文本、表格或结构化数据。
- **支持生成/写入**：表示工具可以直接创建该格式文件。
- **支持深度保真编辑**：表示可以在尽量保留复杂原始版式的前提下修改原文件。

当前项目：
- 对 `xlsx / docx / pptx / pdf / csv / json` 有明确工具支持。
- 对 `xls / doc` 是**上传扩展名层面允许**，但**不应宣称为已实现结构化可靠处理**。
- 不应宣称支持 OCR、扫描版 PDF 识别、复杂 Office 原样编辑回写。

## 2. 当前支持矩阵

| 文件类型 | 可上传 | 可读 | 可写/生成 | 当前建议定位 |
| --- | --- | --- | --- | --- |
| `.xlsx` | 是 | 是 | 是 | Excel 主力格式，优先推荐 |
| `.xls` | 是 | 不建议承诺 | 不建议承诺 | 仅作上传存在，不作为可靠结构化处理目标 |
| `.docx` | 是 | 是 | 是 | Word 主力格式，优先推荐 |
| `.doc` | 是 | 不建议承诺 | 不建议承诺 | 不应说成可稳定解析/写回 |
| `.pptx` | 未在上传白名单单独限制中阻止 | 是 | 是 | 可读摘要、可生成轻量演示稿 |
| `.pdf` | 是 | 是 | 是 | 可读文本、可生成、可合并 |
| `.csv` | 是 | 是 | 是 | 轻量结构化数据交换 |
| `.json` | 是 | 是 | 是 | 结构化数据交换 |
| 图片（png/jpg/webp/gif 等） | 是 | 部分信息读取 | 部分生成/压缩 | 适合信息读取、压缩、插入 PPT |
| `.zip` | 是 | 是（列表/信息） | 是（压缩/解压） | 文件打包与分发 |

> 说明：上传接口限制的是单文件大小和文件数量，不等价于业务语义上的“完全支持”。

## 3. Excel（仅对 `.xlsx` 给出可靠承诺）

### 已实现能力
适合明确描述为：

- 读取 `.xlsx` 工作簿
- 指定工作表读取
- 返回工作表列表、列信息、合并区域
- 返回单元格值、公式结果、部分样式信息
- 新建 `.xlsx`
- 追加行数据到已有 `.xlsx`
- 支持结构化写入：
  - `headers`
  - `rows`
  - `columns`
  - `merges`
  - `views`
  - `autoWidth`
- 支持单元格常见配置：
  - `value`
  - `formula`
  - `result`
  - `font`
  - `fill`
  - `alignment`
  - `border`
  - `numFmt`
- 支持把 Markdown 表格、逗号/Tab/竖线分隔文本转换为表格写入

### 不应夸大的点
- 不应说“完整保留原 Excel 所有高级对象”
- 不应承诺支持宏、数据透视表对象、复杂图表对象、VBA、外部连接
- 不应把 `.xls` 说成和 `.xlsx` 一样可靠
- 不应承诺对复杂公式链路做语义级修复

### 最佳实践
- 用户要结构化处理表格时，优先引导使用 `.xlsx`
- 涉及多表、样式、合并单元格时，先说明“可处理常见结构，但复杂格式需复核”
- 若用户给的是 `.xls`，建议先转换为 `.xlsx` 再继续

---

## 4. Word（仅对 `.docx` 给出可靠承诺）

### 已实现能力
- 读取 `.docx` 纯文本
- 把 `.docx` 转为 HTML
- 生成真正的 `.docx`
- 生成的 `.docx` 支持：
  - 标题
  - 段落
  - 空行
  - 有序/无序列表
  - 基础表格
  - 基础行内样式（加粗、斜体、下划线、字体大小、颜色等）
- 支持把 Markdown 自动解析为 docx 中的标题/段落/列表/表格/代码块
- 输出页面按 A4 尺寸生成

### 不应夸大的点
- 不应说支持复杂页眉页脚、批注、修订、目录域、脚注、复杂分栏等高级 Word 能力
- 不应说能高保真修改已有复杂排版的原始 `.docx`
- 不应把 `.doc` 说成稳定支持
- 不应承诺“完全还原原文档视觉样式”

### 最佳实践
- 新建文档、报告、纪要、制度稿，优先走 `.docx` 生成
- 需要“读取内容做总结/改写”时，可先读 `.docx` 纯文本或 HTML，再生成新的 `.docx`
- 如果用户强调“原版式必须完整保留”，要提前提醒当前能力更适合**内容级生成**，不适合**复杂版式保真编辑**

---

## 5. PowerPoint（对 `.pptx` 给轻量承诺）

### 已实现能力
- 读取 `.pptx` 的基础文本内容
- 返回页数、每页标题、文本摘要、粗略 bullet 数
- 生成 `.pptx`
- 生成时支持：
  - 标题
  - 正文
  - bullet 列表
  - 基础表格
  - 图片页
  - 基础图表页
  - 数据卡片页
  - 简单模板主题（如 `default / executive / growth`）
  - 备注 notes

### 不应夸大的点
- 不应说支持复杂动画、母版精修、SmartArt、复杂版式复刻
- 不应说能高保真编辑已有精美 PPT 模板
- 不应承诺专业设计级美化

### 最佳实践
- 适合做“汇报草稿 / 提纲型演示稿 / 数据概览型演示文稿”
- 不适合承诺“像专业设计师做的发布会级 PPT”
- 用户给现成 `.pptx` 时，更适合做内容提取、总结、再生成草稿，而不是精细改样式

---

## 6. PDF

### 已实现能力
- 读取 PDF 文本内容
- 返回页数、文本长度、基础元信息
- 生成 PDF
- 支持 Markdown 渲染生成 PDF
- 支持纯文本写入 PDF
- 支持多个 PDF 合并
- 尝试加载中文字体；若环境缺少可用中文字体，中文支持会受限

### 不应夸大的点
- 不应说支持 OCR
- 不应说能稳定识别扫描版 PDF
- 不应说能直接编辑现有 PDF 的复杂版面元素
- 不应说可以精确保留原 PDF 的表格与版式结构后再编辑

### 最佳实践
- 文本型 PDF：适合摘要、提取、合并、再输出
- 扫描版 PDF：应提前提醒“可能读不到有效文字”
- 若用户要“改原 PDF 的某几处版面内容”，应说明当前更适合**重新生成新 PDF**，不适合**版面级编辑**

---

## 7. CSV / JSON

### CSV 已实现能力
- 读取 CSV
- 解析为 `headers + data`
- 写入 CSV

### CSV 限制
- 解析器是轻量实现
- 适合普通逗号分隔文本
- 不应夸大为“完整兼容所有复杂 CSV 方言”
- 对复杂嵌套引号/极端换行场景要谨慎

### JSON 已实现能力
- 读取 JSON
- 写入 JSON
- 支持 pretty 格式输出

### 最佳实践
- 结构化数据交换优先考虑 `json`
- 需要给 Excel/BI 工具继续处理时可输出 `csv`

## 8. 文件上传与工作区约束

当前项目中与用户使用强相关的约束：

### 上传接口约束
- 单文件最大：**5MB**
- 单次最多：**10 个文件**

### 用户 workspace 约束
- 总存储配额：**50MB**
- 每个用户最多文件数：**100 个**

### 内容搜索默认限制
- 默认最多扫描 **30 个文本文件**
- 单文件默认最多读取 **256KB**
- 默认总读取最多 **2MB**

### URL 访问特点
- workspace 文件访问链接为**签名链接**，会过期

## 9. Agent 回答时的推荐判断模板

### 用户说“帮我处理 Excel”
优先判断：
1. 是否是 `.xlsx`
2. 是读取分析、还是要生成新表
3. 是否要保留复杂格式/公式
4. 是否涉及多 sheet / 合并单元格 / 样式

推荐说法：
- 如果是 `.xlsx`，可直接读取结构并生成新结果文件
- 如果是 `.xls`，建议先转成 `.xlsx`
- 如果要求完整保留复杂原样式，需要提醒当前更适合结构化处理，不保证完全保真

### 用户说“帮我改 Word 文档”
优先判断：
1. 是否是 `.docx`
2. 是改内容，还是保持复杂原排版
3. 是否接受生成新的 `.docx`

推荐说法：
- 适合读取内容后生成新的 `.docx`
- 不适合承诺复杂版式原样微调

### 用户说“帮我处理 PDF”
优先判断：
1. 是文本 PDF 还是扫描件
2. 是提取/总结/合并，还是要编辑原版面

推荐说法：
- 文本 PDF 可提取和重组
- 扫描版可能无法稳定识别文字
- 复杂版面编辑不属于当前强项

## 10. 不可误导清单

Agent 不应主动宣称以下能力已经实现：

- 支持 OCR 扫描识别
- 稳定处理 `.doc` 老格式 Word
- 稳定处理 `.xls` 老格式 Excel
- 高保真编辑复杂 Word / PPT / PDF 原文件样式
- 支持宏、VBA、复杂透视表对象、复杂图表对象迁移
- 支持扫描版 PDF 表格精准提取
- 支持发布会级 PPT 设计自动化

---

## 11. 推荐输出策略

当用户需求超出边界时，优先采用以下降级策略：

1. **先读取再说明边界**
2. **先提取文本/结构，再生成新文件**
3. **建议用户转换格式**（如 `xls -> xlsx`, `doc -> docx`）
4. **明确提示需人工复核的部分**
5. **优先给出当前实现可完成的最稳方案**

---

## 12. 一句话总结

本项目当前的 Office/file 强项是：

- 基于 workspace 的安全文件处理
- `.xlsx / .docx / .pptx / .pdf / .csv / .json` 的**轻到中度结构化处理与生成**
- 适合“读取、提取、整理、汇总、再生成”

本项目当前不应被描述为：

- 通用高保真 Office 编辑器
- OCR 系统
- 复杂旧格式兼容引擎
