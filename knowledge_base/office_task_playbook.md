# Excel / Word / PDF / PPT 任务处理指南（对齐当前能力）

本文面向 Agent 的任务判断，不写“泛 Office 教程”，只写**当前项目能稳定支撑的任务模式**。

---

## 1. 任务分流总规则

收到文件处理需求时，先判断成下面四类之一：

1. **读取分析型**
   - 例如：总结、提取、统计、找差异、整理要点
2. **结构化重写型**
   - 例如：根据已有内容重新生成 Excel / Word / PPT / PDF
3. **追加记录型**
   - 例如：给现有 Excel 日志表追加新行
4. **复杂保真编辑型**
   - 例如：要求原格式几乎不变，只改几个版面细节

其中：
- 前 3 类通常适合当前项目
- 第 4 类必须谨慎，不应直接承诺

---

## 2. Excel 任务指南（主推 `.xlsx`）

### 2.1 适合做的任务

#### 场景 A：读取表格并做汇总分析
常见表达：
- 帮我看看这个销售表
- 统计每个人的业绩
- 按月份汇总
- 看看有没有空值/异常值

推荐处理：
1. 读取 `.xlsx`
2. 判断工作表、列名、行数
3. 识别是否存在合并单元格、公式、日期列
4. 输出分析结果或生成新的结果表

适合输出：
- 文本总结
- 新的 `.xlsx`
- `.csv` / `.json` 中间结果

#### 场景 B：新建结构化报表
常见表达：
- 帮我生成一个日报模板
- 按这个字段做一个 Excel
- 做一个统计表

推荐处理：
- 直接生成新的 `.xlsx`
- 使用 headers / rows / columns / merges / autoWidth
- 如果只是轻量表格，也可以先用 Markdown 表格表达后再生成

#### 场景 C：向现有工作簿追加记录
常见表达：
- 往这张日志表继续追加今天的数据
- 新增几行记录

推荐处理：
- 使用追加模式
- 仅在单工作表场景下追加更稳
- 如用户未指定 sheet，提醒默认会落到首个或指定工作表

---

### 2.2 先澄清的问题
在这些情况下先问清楚：

- 是 `.xlsx` 还是 `.xls`？
- 需要读哪个工作表？
- 是否允许覆盖原文件？
- 是否必须保留原公式和复杂样式？
- 输出是新文件还是直接追加到现有文件？

---

### 2.3 风险提醒模板
可使用类似说法：

- 当前对 `.xlsx` 的结构化读取和生成支持较好，若是 `.xls` 建议先转换为 `.xlsx` 再处理。
- 可以保留常见表格结构与部分样式，但不建议承诺宏、复杂透视表、外部连接等高级对象完整保真。
- 如果你的目标是“原表几乎不动，只修几个复杂格式细节”，当前更适合生成新结果表后人工复核。

---

## 3. Word 任务指南（主推 `.docx`）

### 3.1 适合做的任务

#### 场景 A：读取文档内容并总结/改写
常见表达：
- 帮我提炼这份文档重点
- 把这篇文档改成正式一点
- 根据这份材料整理纪要

推荐处理：
1. 读取 `.docx` 纯文本或 HTML
2. 提取结构信息
3. 输出摘要或生成新的 `.docx`

#### 场景 B：生成新文档
常见表达：
- 帮我生成会议纪要
- 按这个提纲做个 Word 文档
- 输出一份方案文档

推荐处理：
- 直接生成 `.docx`
- 使用标题、段落、列表、基础表格
- 如果用户提供 Markdown，可优先走 Markdown -> docx

---

### 3.2 适合的文档类型
- 会议纪要
- 工作总结
- 实施方案
- 制度草稿
- 产品说明
- 培训材料
- 简单报告

---

### 3.3 不应直接承诺的事情
- 保留复杂原页眉页脚并局部微调
- 保留原修订模式、批注、目录域、脚注体系
- 复杂排版完全不变
- `.doc` 老格式的稳定解析与写回

---

### 3.4 推荐话术
- 如果你接受生成一份新的 `.docx`，当前方案比较稳。
- 如果你要求保持原文档复杂排版几乎不变，只做局部视觉修改，这不属于当前实现的强项。
- 如果文件是 `.doc`，建议先转成 `.docx` 再处理。

---

## 4. PDF 任务指南

### 4.1 适合做的任务

#### 场景 A：读取文本 PDF 并总结
常见表达：
- 提取 PDF 要点
- 帮我总结这份 PDF
- 找出合同里的关键条款

推荐处理：
- 读取文本
- 摘要 / 改写 / 提炼结构
- 必要时生成新的 Word / PDF / Markdown

#### 场景 B：合并多个 PDF
常见表达：
- 把这几个 PDF 合成一个
- 合并章节文件

推荐处理：
- 直接使用 PDF 合并能力

#### 场景 C：生成新 PDF
常见表达：
- 把这份报告导出 PDF
- 生成一份 PDF 版本

推荐处理：
- 用 Markdown 或纯文本生成新 PDF

---

### 4.2 先澄清的问题
- 是文本 PDF 还是扫描件？
- 是要提取内容，还是编辑原页面版式？
- 是否接受“重新生成一个新的 PDF”而不是修改原 PDF？

---

### 4.3 边界提醒
- 扫描版 PDF 可能读不到有效文字
- 当前不应承诺 OCR
- 当前更适合“读取文本 -> 生成新 PDF”，不适合“原版面精修”
- 中文 PDF 输出依赖运行环境中的可用中文字体

---

## 5. PPT 任务指南（轻量演示稿）

### 5.1 适合做的任务

#### 场景 A：生成汇报草稿
常见表达：
- 帮我做个季度汇报 PPT
- 把这份文档转成演示提纲
- 生成一个培训课件框架

推荐处理：
- 输出轻量 `.pptx`
- 每页组织成：标题 + 正文/要点/表格/图表/图片
- 适合“内容成稿”，不适合“设计成品”

#### 场景 B：读取现有 PPT 内容
常见表达：
- 看看这个 PPT 在讲什么
- 帮我整理每页重点

推荐处理：
- 读取基础文本摘要
- 再总结、重组、生成新版草稿

---

### 5.2 推荐使用场景
- 周报/月报汇报
- 项目复盘
- 经营数据简报
- 培训提纲
- 客户方案初稿

### 5.3 不应承诺的事情
- 动画设计
- 母版级统一改造
- SmartArt/复杂图形完美保留
- 专业设计师级美观度

---

## 6. CSV / JSON 指南

### 6.1 CSV 适合场景
- 数据导出
- 轻量二维表交换
- 给 Excel 再处理

### 6.2 JSON 适合场景
- 结构化结果输出
- 系统配置
- 中间处理结果存档

### 6.3 注意事项
- CSV 解析适合普通场景，不要夸大为复杂 CSV 兼容引擎
- 若字段含复杂嵌套结构，优先输出 JSON

---

## 7. 文件处理前的标准确认清单

遇到文件类需求，优先确认：

1. 输入文件格式是什么？
2. 目标是读取分析、生成新文件，还是修改原文件？
3. 是否允许覆盖原文件？
4. 是否要求复杂格式/样式原样保留？
5. 输出期望格式是什么？
6. 文件大小和数量是否可能超出限制？

---

## 8. 适合直接执行 vs 适合先确认

### 适合直接执行
- 读取 `.xlsx` 并总结
- 生成新的 `.docx`
- 合并多个 PDF
- 生成简单 `.pptx`
- 读写 CSV / JSON
- 给现有 `.xlsx` 追加几行数据

### 适合先确认
- `.xls` / `.doc` 老格式文件
- 扫描版 PDF
- 要求原复杂版式不变的 Word/PDF/PPT
- 涉及大量文件或大文件上传
- 要覆盖原文件但用户未明确授权

---

## 9. 推荐降级方案

当需求超过边界时，优先这样处理：

### 降级方案 1：转换格式
- `xls -> xlsx`
- `doc -> docx`

### 降级方案 2：先提取内容，再生成新文件
- 原文件复杂难改时，转成“读取 -> 重写”模式

### 降级方案 3：只输出结构化内容
- 先给 JSON / Markdown / 提纲，再让用户确认后导出 Office 文件

### 降级方案 4：提示人工复核
- 尤其是涉及复杂样式、合同、财务报表、扫描 PDF 时

---

## 10. 面向 Agent 的一句话工作准则

当前项目最稳的文件处理策略是：

**优先做结构化读取、总结、整理和新文件生成；谨慎承诺复杂旧格式兼容与高保真原文件编辑。**
